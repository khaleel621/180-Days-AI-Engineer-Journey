### Python: OOP — Polymorphism, Method Overloading and Method Overriding

Implemented and tested `01-python-fundamentals/day18-polymorphism.py`:

**Concepts learned:**
- Polymorphism: one interface (method name) with many different implementations; the same method call behaves differently depending on the object.
- Method overriding: a child class redefines a parent class method (`Dog.make_sound()`, `Cat.make_sound()`, `Cow.make_sound()` override `Animal.make_sound()`).
- Method overloading in Python: Python does NOT support traditional overloading; use `*args` / `**kwargs`, default arguments, or `isinstance()` checks instead.
- Duck typing: "If it walks like a duck and quacks like a duck, it's a duck" — any object with a `.speak()` method works with `make_it_speak()`, regardless of inheritance.

**Exercises implemented:**
1. `Animal` base class with `make_sound()` returning a generic sound.
2. `Dog(Animal)`, `Cat(Animal)`, `Cow(Animal)` — each overrides `make_sound()`.
3. `animal_sound(animal)` — polymorphic function that works with any Animal subclass.
4. `Calculator.add(*args)` — Python-style method overloading handling 0, 1, 2, or 3 numeric arguments; rejects non-numeric input with `TypeError`.
5. `DogDuck`, `CatDuck`, `RobotDuck` — classes with no common parent, each with a `.speak()` method.
6. `make_it_speak(obj)` — duck typing function that calls `.speak()` on any object that has it.

**Tests:** `test_day18_polymorphism.py` - all 15 tests passed, covering method overriding, polymorphism with multiple objects, Calculator overloading with various argument counts, type validation, and duck typing with multiple speaking objects.

### DSA: Trapping Rain Water (Two Pointers)

Implemented `trap(height)` in `02-data-structures-algorithms/two-pointers/day18-trapping-rain-water.py`:

**Concepts learned:**
- Trapping Rain Water: compute how much water can be trapped after raining given an elevation map.
- Two Pointers approach: `left` and `right` pointers start at the ends and move inward.
- Track `left_max` and `right_max` — the highest bar seen so far from each side.
- Always process the side with the smaller bar; water level is limited by the lower of the two maximums.
- O(n) time: each index visited at most once. O(1) space: only a few integer variables.

**Examples verified:**
- `[] -> 0`
- `[5] -> 0`
- `[1, 2, 3, 4] -> 0`
- `[4, 3, 2, 1] -> 0`
- `[3, 0, 2, 0, 4] -> 7`
- `[0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1] -> 6`

**Tests:** `test_day18_trapping_rain_water.py` - all 9 tests passed, covering empty list, single element, increasing heights, decreasing heights, equal heights, multiple water-trapping sections, and input immutability.
