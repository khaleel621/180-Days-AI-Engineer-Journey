## Day 20 Topics

### Track A — Python: OOP Encapsulation
- What encapsulation is: bundling data (attributes) and the methods that operate on that data into a single unit (a class), and restricting direct access to some of the object's internal state.
- Public attribute `account_holder_name`, protected `_account_number`, private `__balance` in the `BankAccount` class.
- Private variables using double underscores: `__balance` is name-mangled to `_BankAccount__balance`; direct access from outside raises `AttributeError`.
- Getters and setters via the `balance` property: the getter reads `__balance` safely; the setter validates (no negative balance).
- Why encapsulation is useful: prevents negative deposits and overdrafts, centralizes all validation in one place, and protects object invariants.
- Practical program: `BankAccount` class with `deposit()`, `withdraw()`, `display_balance()`, getters/setters, and beginner-friendly comments.

### Track B — DSA: Minimum Window Substring
- Problem: given strings `s` and `t`, find the smallest substring of `s` containing all characters of `t`, including duplicate character requirements.
- Sliding window + frequency dictionary: `need` (requirements from `t`) and `window_counts` (current window).
- Expand the right edge of the window; track `formed` vs `required` to know when all characters are satisfied.
- Shrink from the left while the window stays valid, recording the smallest valid window.
- Duplicate characters in `t` are handled because `formed` only increases when a character's count meets its required count exactly.
- Returns an empty string `""` when no valid window exists.
- Example: `s = "ADOBECODEBANC"`, `t = "ABC"` → `"BANC"`.
- Time complexity: O(|s| + |t|); Space complexity: O(|s| + |t|).
